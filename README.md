# dsh-session-manager-delete

**DSH 会话删除插件。** 把已经归档的会话从侧栏、磁盘、工作区登记和浏览器本地状态里彻底删掉；删完不需要手动刷新，也不会留下「未分组」幽灵。

> 删除不可撤销。插件不碰工作区目录里的任何文件，也不删附件。

---

## 让 agent 帮你部署

不想自己找 DSH profile、改依赖、重启应用？把下面这段话交给你的编程 agent（DSH 自带的 agent、Claude Code、Codex 都可以）：

> 请帮我安装 DSH 插件 `dsh-session-manager-delete`。
>
> 1. 先读 https://github.com/anheon/dsh-session-manager-delete 的 README，按「安装」一节操作；
> 2. 安装前备份 `~/.dsh/profiles/desktop/package.json`；
> 3. 装完告诉我怎么重启 DSH、怎么验证插件已经加载；
> 4. 不要删除我的任何会话，也不要改我的工作区文件。

Agent 会读文档、找到你的 DSH profile、安装包并把插件加进 bundle 列表。你只需要确认它要改的文件，然后重启 DSH。

## 它解决什么问题

DSH 的一个会话不只是一份日志。它同时存在于五个地方：

1. 宿主进程的 `ctx.sessions` / `ctx.agents` 内存表；
2. `$DSH_HOME/sessions/<工作区>/<会话 id>/` 下的对话日志；
3. `$DSH_HOME/storages/session_projcache/` 下的投影缓存；
4. 工作区登记（`workspace.json` 里的归属、归档、置顶）；
5. 浏览器 localStorage 里的草稿、页签、布局、当前选中。

只删日志，宿主内存还记着它；只注销内存，磁盘上还留着；先摘工作区登记、后删文件，侧栏旧快照就会把它显示成一条「未分组」。本插件按「**关终端 → 注销宿主内存 → 删磁盘 → 摘登记 → 清本地状态 → 重拉列表**」的顺序一次做完，并且在每一步之后复核。

## 能做什么

- 只对**已归档**的会话开放删除；未归档时确认框会直接告诉你怎么归档。
- 支持跨工作区勾选多个已归档会话，一次预览并确认删除。
- 删除前给出完整清单：会话 id、文件与字节数、登记变更、浏览器本地状态、悬空引用、可选连带删除的派生会话。
- 有工作在跑时，给一个默认勾选的「先停掉正在跑的工作」；停完再验一次，停不下来就拒删。
- 子代理会话随父会话一起删（它们在侧栏里本来就没有入口）；fork 出来的可见会话默认保留，可在确认框里勾选一并删除。
- 删除后自动重拉会话列表，不需要手动刷新。
- 旧版本留下的「未分组」幽灵条目，可以在确认框里点「现在清理」，只清登记、不碰磁盘。
- 路径三道校验、同源校验、确认标记、失败即拒删（fail closed）。

## 不做什么

- 不删工作区目录里的代码、文档、附件。
- 不删跨会话共享的 `attachments/`、`cache/`、凭据、profile。
- 不顺着软链/联接去删目标。
- 不碰其他会话的日志、缓存、登记、本地状态。
- 不提供回收站或撤销：删除就是删除。

## 安装

### 从 npm 安装（推荐）

要求：DSH desktop，Node.js 22 或更高（DSH 自带运行时也可以）。

1. 打开 DSH 的插件管理器（设置里的插件/扩展入口）。
2. 安装 spec 填：

   ```text
   dsh-session-manager-delete
   ```

3. 安装完成后**完全退出并重启 DSH**。宿主半区只有在重启后才会加载。
4. 重启后，在侧栏找一个**已归档**的会话，点它的「…」菜单；能看到「删除会话…」就说明装好了。

> 如果插件管理器用的是国内镜像、暂时搜不到这个包，可以先把 npm registry 切到官方源再装：
>
> ```bash
> npm config set registry https://registry.npmjs.org/
> ```
>
> 装完可以切回原来的镜像。

### 从源码安装（开发/本地修改）

```bash
git clone https://github.com/anheon/dsh-session-manager-delete.git
cd dsh-session-manager-delete
npm test
```

然后在 DSH 插件管理器里安装：

```text
link:<这个目录的绝对路径>
```

安装后重启 DSH。之后改代码的流程是：

```bash
npm run build          # 改了 lib/client.js 必须重新构建
# 重启 DSH
```

### 更新与卸载

- **更新**：在插件管理器里更新/重装，然后**完全退出并重启 DSH**。宿主半区与浏览器半区必须同时换成新代码；只更新一半时，旧 bundle 不会携带清单版本，删除请求会被宿主以 409 拒绝。
- **卸载**：在插件管理器里卸载即可。插件不写自己的状态文件，卸载后没有额外残留。

升级后可以核对真正装上的版本（不是看有没有报错）：

```bash
node -p "require('<profile 目录>/node_modules/dsh-session-manager-delete/package.json').version"
```

完整的版本变更见 [CHANGELOG.md](CHANGELOG.md)。

## 使用

1. 在侧栏把要删的会话**归档**（「…」→「归档」）。
2. 再点「…」→「删除会话…」。
3. 读完确认框里的清单，勾选底部的确认框，点危险按钮。

确认框里会写清楚：

- 会话标题、id、归档状态、占用空间、记录条数、创建时间、工作目录；
- 要删的日志、投影缓存、spill 临时目录、空目录；
- 要摘的工作区登记、要清的浏览器本地状态；
- 旧幽灵的悬空引用（如果有），以及「现在清理」入口；
- 有工作在跑时的「先停掉」勾选；
- 可选连带删除的 fork 列表（勾选后清单会更新，包含 fork 及其子代理的日志、登记和本地状态；fork 自己也必须已归档）；
- 哪些东西**不会**被删。

删除成功后，插件会调用 DSH 的 `ctx.sessions.refresh()` 重拉权威列表。正常情况下侧栏里的那一行会直接消失，不需要刷新页面。

如果重拉失败（宿主服务掉线等），完成页会明确写「侧栏列表没有刷新成功……刷新页面就会消失」，不会把已经完成的删除说成失败。

### 批量删除

1. 在任意已归档会话的「…」菜单点「批量删除会话…」。打开弹窗时会勾选这条会话。
2. 按工作区挑选会话，或按标题搜索。「全选当前结果」只勾选搜索命中的条目。切换搜索会保留原有勾选，底部会显示被筛选隐藏的勾选数量。
3. 点「预览删除」，核对每条会话及其子代理、预计释放的空间。Fork 会话需要单独勾选。有条目变得不可删时，按提示把它移出，再确认更新后的清单。
4. 勾选永久删除确认框并提交。结果页逐项显示处理结果。完成的会话会自动从侧栏移除，其他条目可以重新预览后再试。

一次最多删除 200 个会话，包含会随选中会话一起删除的子代理。

### 已经删过、但界面还留着「未分组」怎么办

那是旧版本留下的悬空登记。打开任意一个已归档会话的删除确认框，点「现在清理」；它只走工作区登记的官方接口，不删任何会话。也可以重启一次 DSH，之后不会再产生新的。

## 删除范围

| 位置 | 处理 |
| --- | --- |
| 宿主内存 | 从 `ctx.sessions` 与 `ctx.agents` 注销，发出配对的 `disposed` 事件 |
| 对话日志 | 递归删除 `$DSH_HOME/sessions/<工作区>/<会话 id>/` |
| 投影缓存 | 删除 `$DSH_HOME/storages/session_projcache/sessions/<id>.json` 及其备份 |
| spill 临时目录 | 按会话 id 的 sha256 前缀精确指认，尽力删除 |
| 空工作区目录 | 只收走这次删完确实变空的 slug 目录 |
| 工作区登记 | 取消置顶、取消归档、移出工作区；再清悬空引用 |
| 浏览器本地状态 | 删会话私有键，定点摘共享键里的引用 |
| 侧栏列表 | 调用 `ctx.sessions.refresh()` 重拉 |

**不会删**：`attachments/`、`cache/`、凭据、profiles、工作区里的代码/文档、其他会话、软链/联接的目标、`<TEMP>/dsh-workspace-changes-*`。

完整的键名与清理规则见 [docs/DESIGN.md](docs/DESIGN.md)。

## 安全设计

| 闸门 | 规则 | 不过时 |
| --- | --- | --- |
| 身份与路径 | 会话 id 必须是小写 `(session-)?<uuid>`；拼出的路径要过字符串、lstat、realpath 三道校验 | 拒绝，什么都不动 |
| 归档 | 只删已归档会话；归档状态读不到也拒删 | 409 |
| 活动 | 对删除集合里每个会话问一次官方活动瀑布；有工作在跑时先停再验 | 409 |
| 注销能力 | 两个宿主注册表必须是 `store` Map + `detachEntered` 形状 | 拒绝，什么都不动 |
| 确认 | POST 必须带 `confirm: 'delete-session'`，界面还要勾选确认框 | 400 |
| 同源 | `Sec-Fetch-Site` 只接受 same-origin/none；删除要求 Origin/Host 同源且 Host 是 IP 字面量或 localhost | 403 |
| 清单 | 确认时提交预览版本，宿主复核会话、路径与登记范围；确认框会另列需补写落盘的会话 | 409，重新预览并确认 |
| 复核 | 注销后复核内存，删完复核磁盘，摘完复核登记 | 409 / 500，如实报告 |

删除顺序本身也是安全设计：

```mermaid
flowchart LR
  A[已归档会话] --> B[生成并展示清单]
  B --> C[关闭会话名下终端]
  C --> D[注销宿主内存]
  D --> E[删投影缓存]
  E --> F[删对话日志]
  F --> G[摘工作区登记]
  G --> H[清浏览器本地状态]
  H --> I[重拉侧栏列表]
```

- **先关终端再注销**：终端按属主对象身份匹配，注销后就找不到那个对象了。
- **先删可重建的缓存，最后删日志**：整批缓存清理和复核都通过后才开始删日志；缓存阶段失败时保留日志和登记。
- **删干净才摘登记**：否则会留下「界面里没有、磁盘上还在」的孤儿。
- **注销没生效就拒删**：宁可不让删，也不硬删之后留一颗刷新去不掉的幽灵。

## HTTP 接口

插件注册一条同源路由：`/dsh-session-manager-delete/api`。

| 请求 | 作用 |
| --- | --- |
| `GET /dsh-session-manager-delete/api?id=<sessionId>&extraRoots=<forkId>` | 只读预览。每个选中的 fork 对应一个可选的 `extraRoots` 参数，可删除时返回 `session.preview` |
| `POST /dsh-session-manager-delete/api` `{id, confirm, preview, dangling, extraRoots?, stop?}` | 删除。带上同一组选项和最近一次确认的 `session.preview` |
| `POST /dsh-session-manager-delete/api` `{repair: true, confirm}` | 只清工作区登记里的悬空引用，不删磁盘 |
| `GET /dsh-session-manager-delete/api?batch=candidates` | 列出可在批量弹窗中选择的已归档会话 |
| `POST /dsh-session-manager-delete/api` `{action: 'preview-batch', ids}` | 只读预览多条选中会话及其子代理 |
| `POST /dsh-session-manager-delete/api` `{action: 'delete-batch', ids, preview, confirm, stop?}` | 提交同一份已确认清单。若执行中部分完成，返回逐项结果与已确认删除的 ID |

返回状态：

| 状态 | 含义 |
| --- | --- |
| 200 | 全部复核通过 |
| 400 | id/请求体/清单形状不对，或超过 200 条；什么都没动 |
| 403 | 跨站或 Host 不是 IP 字面量/localhost；什么都没动 |
| 404 | 会话已经不存在；没什么可删的 |
| 409 | 清单变化、取消归档、注销或活动检查未通过、目标超过 200。清单变化时返回 `PREVIEW_CHANGED`，客户端应重新预览并确认 |
| 413 | 请求体过大；什么都没动 |
| 500 | 文件操作或磁盘复核失败。缓存阶段失败时保留日志和登记；终端可能已关、宿主内存可能已注销 |

成功不是「试过了」，而是注销后复核、删完扫盘、摘完查登记都通过才回 200。

## 开发与验证

要求 Node.js 22+。项目没有运行时依赖，测试也不需要安装依赖。

```bash
# 构建浏览器半区（改了 lib/client.js 必须重跑）
npm run build

# 检查 bundle 是否过期（不写文件）
npm run check:bundle

# 宿主端到端测试
npm run check:host

# 浏览器半区行为测试
npm run check:client

# 全部：构建 + 宿主 + 浏览器
npm test
```

`scripts/verify-host.mjs` 在临时 `DSH_HOME` 里搭真实形状的夹具：父会话、子代理、fork、未归档、运行中、未落盘、软链、被占用、悬空引用，外加附件/凭据/工作区登记做诱饵。它像浏览器一样调路由，逐条验证删除范围、闸门、失败语义和复核。

`scripts/verify-client.mjs` 在微型 React、假 DOM、会记账的 localStorage 里跑**构建产物**，验证菜单、确认框、勾选、删除、本地状态清理、超时、迟到响应、焦点归还和卸载清理。

GitHub Actions 用 Node 22 + Windows 跑同一套，并且先跑 `npm run check:bundle` 防止 `client.bundle.js` 漂移。

## 已知边界

- **只能删已归档会话**；归档状态读不到时也会拒删。
- **只看得到当前宿主进程**：同机另一个进程共享 `DSH_HOME` 时，它跑的回合、它持有的会话不在保护范围内。
- **日志在软链/联接后面时拒删**：插件不顺着链接删，会明确说明让你手动处理。
- **附件不回收**：附件是跨会话共享的内容寻址对象，DSH 没有按会话回收的机制。
- **`<TEMP>/dsh-workspace-changes-*` 认不出来**：目录名是随机串、不带会话 id，插件不猜。
- **自定义域名/反向代理下删除会被拒**：Host 必须是 IP 字面量或 localhost，用来挡 DNS rebinding；查询不受影响。
- **一次最多 200 条**：待删目标或悬空引用超过 200 时，请分批处理；超出会明确报错，不会静默截断。
- **删除不可撤销**：没有回收站，也没有撤销。
- **重拉列表失败不算删除失败**：文件已经删了，完成页会提示手动刷新。
